# Current live-reference study - 2026-11-13

This study was made while improving Atlas, not while changing a demo. It demonstrates honest research across several domains. It is not a list of universal templates, an award ranking, or a guarantee that these pages remain unchanged.

## Method

- Searched for current sources, then opened the actual brands' public pages.
- Captured anonymous desktop (1440x900) and mobile (390x844) views.
- Opened the retained screenshots and meaningful middle captures where available.
- Recorded content extraction separately from visual evidence.
- Clicked no consent choices, region selections, forms, purchases, bookings or account actions.
- Used a longer settling interval after the initial Linear entrance was incomplete.
- Kept blocked, gated and incomplete references as limitations rather than pretending every capture succeeded.

Capture timestamps use UTC; the inspection date here uses Asia/Jakarta. ?Inspected on this date? does not establish a launch/redesign date. No performance, accessibility conformance, award or conversion claim is made.

Detailed observations, limitations and exact image paths are in [sources.json](sources.json).

## Synthesis for the skill

The useful commonality is not a shared palette or hero. These sites make different kinds of evidence prominent: object, workflow, programme, work or product family.

Atlas therefore requires:
- Research questions tied to a visitor decision.
- Current multi-source inspection for a new direction.
- A distinction between fact, observation and interpretation.
- Multiple composition candidates that differ structurally.
- Explicit adaptation and rejection notes.
- A useful interaction opportunity, not a quota of effects.
- Typography and mobile judgments based on real content.
- A fresh critique after implementation.

A single reference can suggest a mechanism; it cannot justify copying its identity. Nor should the response to a generic split hero always be a full-screen photograph.

## Technical documentation checked

- [MDN text-wrap](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-wrap): wrapping modes and browser compatibility.
- [MDN font-size-adjust](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-size-adjust): metric-related fallback considerations.
- [MDN length units](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length): small/dynamic viewport-unit behavior.
- [Web Vitals](https://web.dev/articles/vitals): distinguish performance targets and field/lab evidence.
- [WCAG target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): minimum criterion and exceptions, distinct from Atlas's comfort target.
- [WCAG text spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html): resilience to user text-spacing adjustments.

These documents are primary technical references, not evidence that every feature should be used. Check current support and the actual project's version again when implementing.

## Evidence availability

## Refresh rule

For a new project, browse again. Update the ledger when the topic, audience, assets or direction changes. Do not present this dated study as fresh research for a future assignment.
