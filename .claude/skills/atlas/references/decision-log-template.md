# Atlas decision log

Use for choices that affect the result or maintenance. Do not record every CSS class.

| Decision | Context and evidence | Alternatives | Chosen approach and reason | Cost/trade-off | Recheck trigger |
|---|---|---|---|---|---|

## Simplification example

- Need: optional FAQ detail with keyboard access.
- Alternative: custom state, event handlers and accordion package.
- Chosen: native details/summary, styled with existing tokens.
- Reason: it provides the required disclosure behavior with fewer owners and dependencies.
- Trade-off: if a future requirement needs coordinated multi-panel state, reconsider rather than overbuilding now.

## Visual example

- Need: communicate a furniture studio using available room and object references.
- Alternatives: a room scene, an isolated-object catalogue, or a material journal.
- Chosen: whichever is supported by the actual brief and assets, not a fixed Atlas preference.
- Rejected transfer: invented workshop photography or a signature layout copied from another brand.
- Recheck: new actual product assets, changed business action or mobile evidence revealing a better composition.
